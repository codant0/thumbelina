# Thumbelina 分阶段实施计划

## 概述

本计划将Thumbelina的开发分为4个阶段，每个阶段包含多个可独立完成的任务。每个任务预计耗时2-5分钟，采用TDD（测试驱动开发）方式：先写测试 → 观察失败 → 实现代码 → 观察通过 → 提交。

---

## 第一阶段：核心框架 + CLI接口

**目标**：构建基础代理系统，支持简单的命令行对话。

### 任务1：项目初始化

**目标**：创建Python项目结构，配置依赖管理。

**步骤**：
1. 创建项目目录结构
2. 配置pyproject.toml（使用Poetry或pip）
3. 创建基础配置文件
4. 添加.gitignore

**预期结构**：
```
thumbelina/
├── src/
│   └── thumbelina/
│       ├── __init__.py
│       ├── main.py
│       └── config.py
├── tests/
├── docs/
├── pyproject.toml
└── README.md
```

**测试**：验证项目可以正常导入和运行。

---

### 任务2：LLM提供商抽象层

**目标**：创建统一的LLM接口，支持多个提供商。

**步骤**：
1. 定义抽象基类`LLMProvider`
2. 实现OpenAI提供商
3. 实现Anthropic提供商
4. 实现Ollama提供商（本地模型）
5. 创建提供商工厂

**接口设计**：
```python
class LLMProvider(ABC):
    @abstractmethod
    async def chat(self, messages: list[dict]) -> str:
        pass
    
    @abstractmethod
    async def stream(self, messages: list[dict]) -> AsyncGenerator[str, None]:
        pass
```

**测试**：验证每个提供商可以正常调用（使用mock）。

---

### 任务3：基础代理循环

**目标**：使用LangGraph创建基础代理循环。

**步骤**：
1. 定义代理状态（State）
2. 创建代理节点（Nodes）
3. 定义条件边（Conditional Edges）
4. 编译并运行代理图

**代理流程**：
```
用户输入 → LLM处理 → 工具调用（如有） → 响应生成
```

**测试**：验证代理可以处理简单对话。

---

### 任务4：基础记忆系统

**目标**：实现对话历史存储和检索。

**步骤**：
1. 创建SQLite数据库模型
2. 实现对话仓库（Repository）
3. 实现会话管理
4. 集成到代理循环

**数据模型**：
```python
class Conversation:
    id: str
    created_at: datetime
    updated_at: datetime

class Message:
    id: str
    conversation_id: str
    role: str  # user, assistant, system
    content: str
    created_at: datetime
```

**测试**：验证对话可以保存和检索。

---

### 任务5：CLI接口

**目标**：创建命令行对话界面。

**步骤**：
1. 创建CLI入口点
2. 实现交互式对话循环
3. 添加历史命令支持
4. 添加退出命令

**功能**：
- 启动命令：`thumbelina chat`
- 交互式对话
- 历史记录（上下键）
- 退出命令：`/exit` 或 `Ctrl+C`

**测试**：验证CLI可以正常启动和退出。

---

### 任务6：配置管理

**目标**：实现配置文件管理。

**步骤**：
1. 定义配置模型（Pydantic）
2. 支持YAML配置文件
3. 支持环境变量覆盖
4. 创建默认配置

**配置项**：
```yaml
llm:
  provider: openai
  model: gpt-4
  api_key: ${OPENAI_API_KEY}

memory:
  database_url: sqlite:///data/thumbelina.db

logging:
  level: INFO
```

**测试**：验证配置可以正常加载和解析。

## 第二阶段：Web界面 + 增强记忆系统

**目标**：创建REST API和WebSocket支持。

**步骤**：
1. 创建FastAPI应用
2. 定义REST API端点
3. 实现WebSocket处理器
4. 添加CORS支持

**API端点**：
- `POST /api/chat` - 发送消息
- `GET /api/conversations` - 获取对话列表
- `GET /api/conversations/{id}` - 获取对话详情

**测试**：验证API端点可以正常响应。

## 风险和缓解措施

### 技术风险
1. **LangGraph学习曲线**：提前学习和实验
2. **LLM API稳定性**：实现重试和降级机制
3. **向量数据库性能**：选择合适的数据库，优化索引

### 进度风险
1. **任务依赖**：合理安排任务顺序
2. **技术难点**：预留缓冲时间
3. **需求变更**：保持设计灵活性

### 质量风险
1. **测试覆盖**：严格执行TDD
2. **代码审查**：定期进行代码审查
3. **文档维护**：及时更新文档
